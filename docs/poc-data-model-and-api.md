# POC data model and API contract

This document fixes the minimum data shape and HTTP contract for the two-week POC. It supports report creation, a redacted public board, and manual claim review. It does not add the later verification, matching, custody, or disposal workflows.

## Item lifecycle

Keep report kind separate from lifecycle status:

- `kind`: `lost` or `found`
- `status`: `open`, `pending_review`, or `returned`

New reports start as `open`. A submitted claim moves an `open` found item to `pending_review`. Admin rejection returns it to `open`; admin confirmation/return sets it to `returned`. Lost reports can remain `open` until manually resolved. Public reads include only `open` items, so a pending claim does not expose a report while it is under review.

## Minimum records

### Item

Collection: `items`

| Field | Type | Notes |
|---|---|---|
| `_id` | ObjectId | Generated by MongoDB |
| `kind` | enum | `lost` or `found` |
| `status` | enum | `open`, `pending_review`, `returned` |
| `title` | string | Required, short public description |
| `description` | string | Required; public-safe description only |
| `category` | string | Controlled value for the POC |
| `location` | string | Controlled campus location value |
| `occurredAt` | date | Approximate date/time; public date may be coarsened if needed |
| `imageUrl` | string | Public URL for the processed image; new reports require an uploaded image |
| `createdAt` | date | Server generated |
| `updatedAt` | date | Server maintained |

Do not place contact details, exact identifying clues, or verification answers on `Item`.

### PrivateDetail

Collection: `privateDetails`, separate from `items`.

| Field | Type | Notes |
|---|---|---|
| `_id` | ObjectId | Generated by MongoDB |
| `itemId` | ObjectId | Unique reference to one item |
| `ciphertext` | string/binary | Authenticated encryption of a versioned payload |
| `keyVersion` | string | Identifies the encryption key version, never the key |
| `createdAt` | date | Server generated |
| `updatedAt` | date | Server maintained |

The encrypted payload may hold reporter name, email/phone, precise location, and non-public identifying details. Keep encryption/decryption in a backend service. Public item queries must never join/read this collection; the public serializer accepts only a public projection/DTO, not database documents.

### ItemImage

Collection: `itemImages`

Store one optimized WebP image per report as binary data. Accept JPEG, PNG, or WebP uploads up to 8 MB; resize to fit within 1280×1280 and re-encode with Sharp, which strips metadata by default. Serve images only while the associated item is publicly open.

### Claim

Collection: `claims`

| Field | Type | Notes |
|---|---|---|
| `_id` | ObjectId | Generated by MongoDB |
| `itemId` | ObjectId | Reference to an open found item |
| `privateCiphertext` | string/binary | Authenticated encryption of claimant name, contact, and optional message |
| `keyVersion` | string | Identifies the encryption key version, never the key |
| `status` | enum | `pending`, `approved`, `rejected` |
| `createdAt` | date | Server generated |
| `reviewedAt` | date or null | Set by admin action |

Keep claim identity and message fields inside the encrypted payload, rather than as plaintext claim columns. Decrypt only in the authorized admin review service.

For the POC, accept one pending claim per item. Enforce with a partial unique index on `itemId` for `status: pending`, or use an atomic conditional update so concurrent requests cannot create competing pending claims. Multiple claims and verification are follow-on work.

### FoundReport

Collection: `foundReports`

When someone browsing the public board finds an item that was reported lost, they can send a private found-item report. Store the finder name, contact, where they found the item, and optional message in the encrypted payload. Keep only the item reference, encrypted fields, status, and timestamps as queryable metadata. Only one pending found report is allowed per item. Submitting it moves the lost item from `open` to `pending_review`; staff approval marks it `returned`, while rejection reopens it.

## Public DTO allowlist

`PublicItem` contains only:

```json
{
  "id": "string",
  "kind": "lost | found",
  "title": "string",
  "description": "string",
  "category": "string",
  "location": "string",
  "occurredAt": "ISO-8601 date",
  "imageUrl": "string | null",
  "createdAt": "ISO-8601 date"
}
```

The public serializer constructs these fields individually from an explicit projection. It never spreads a MongoDB record. It omits `status`, private details, reporter/claimant identity and contact, exact verification clues, moderation notes, and internal timestamps/metadata. Public list and detail endpoints return only `open` items.

## Endpoints

All JSON errors use `{ "error": { "code": "...", "message": "..." } }`.

### `POST /items`

Create a lost/found report as `multipart/form-data`. Required fields are `kind`, `title`, public-safe `description`, `category`, `location`, `occurredAt`, and `image`. Optional private fields are `reporterName`, `reporterContact`, and `privateDetails`. Accept JPEG, PNG, or WebP up to 8 MB; resize and convert to WebP, stripping metadata before storing the binary image in MongoDB. Store the image path on the item, encrypt private fields, and return `201` with `{ "item": PublicItem }`. Never return submitted private fields.

### `GET /images/:id`

Serve the stored WebP image only while an open item references it; return `404` for invalid IDs, missing images, or items that are under review or returned.

### `GET /board?q=&kind=&category=&location=&page=&limit=`

List `open` items only. Return `{ "items": PublicItem[], "page": number, "limit": number, "total": number }`. Apply bounded pagination (default 20, maximum 50) and stable ordering by `createdAt` descending then `_id` descending. Search may be basic text matching.

### `GET /items/:id`

Return one `open` item as `{ "item": PublicItem }`. Return `404` for missing, malformed, or non-open IDs to avoid revealing hidden lifecycle states.

### `POST /claims`

Request: `{ "itemId": "...", "claimantName": "...", "claimantContact": "...", "message": "..." }`. Only accept claims for an `open` found item. Reserve the item with a conditional `open` to `pending_review` update, encrypt claimant name/contact/context into the claim record, and create a `pending` claim. Return `201` with `{ "claim": { "id": "...", "status": "pending", "createdAt": "..." } }`; do not echo contact or claim text. If claim persistence fails, restore the reserved item to `open`.

### `POST /found-reports`

Request: `{ "itemId": "...", "finderName": "...", "finderContact": "...", "foundLocation": "...", "message": "..." }`. Only accept responses for an `open` lost item. Reserve the item with a conditional `open` to `pending_review` update, encrypt finder identity, contact, location, and optional context, and create a pending `FoundReport`. Return only the new response ID and pending status; never return finder details publicly. If persistence fails, reopen the item.

### Minimal admin endpoints

The POC admin surface requires authentication/authorization before exposing decrypted claim details or changing state. The initial implementation uses a configured shared bearer token (`ADMIN_API_TOKEN`) for the demo; replace this with institutional authentication before production.

- `GET /admin/claims?status=pending` returns the review queue with claimant/private data only to an admin.
- `PATCH /admin/claims/:id` accepts `{ "decision": "approved" | "rejected" }`. Set `reviewedAt`; approved claims set the item to `returned`, rejected claims restore it to `open`. Return status only.
- `GET /admin/found-reports?status=pending` returns the possible-match queue with finder details only to an admin.
- `PATCH /admin/found-reports/:id` accepts `{ "decision": "approved" | "rejected" }`. Approval marks the lost item returned; rejection reopens its public listing.
- `PATCH /admin/items/:id/return` may be used instead of approval to mark an item returned manually; set status to `returned` and return `{ "item": { "id": "...", "status": "returned" } }`.

Choose one review/return interaction in the UI. These admin routes are intentionally POC-level and do not implement the full security-role handover flow.

## Persistence and indexes

- `items`: `{ status: 1, createdAt: -1, _id: -1 }`; optional `{ kind: 1, status: 1, createdAt: -1 }` and controlled category/location filters.
- `privateDetails`: unique `{ itemId: 1 }`.
- `claims`: `{ status: 1, createdAt: 1 }`; enforce at most one pending claim per item as described above.
- `foundReports`: `{ status: 1, createdAt: 1 }`; enforce at most one pending found report per item.
- `itemImages`: binary processed image data addressed by the MongoDB `_id`.
- Validate enums, required fields, lengths, and ObjectId inputs at the API boundary. Use server timestamps.

## Privacy acceptance gate

Add an explicit test that serializes fixtures containing sentinel private values and asserts that neither `GET /board` nor `GET /items/:id` contains any sentinel, private field name, or private collection payload. Cover each lifecycle status, including `pending_review` and `returned`, and verify those items are not publicly retrievable. Keep the test as a required POC acceptance check.
